# Quorum for Hypersnap

This standalone browser entry makes Hypersnap public browsing and local signing available without requiring Quorum messenger registration. Quorum's original messenger source, license, fonts, symbol, and theme tokens are preserved in the parent fork. The new web primitives and shell use its semantic tokens; Farcaster wire signing modules are adapted from the MIT-licensed `quorum-shared` source.

## Run

Use Node 22 and Yarn 1.22. `yarn install --frozen-lockfile`, then `yarn dev`. Vite prints the local URL and proxies `/api` to the same public node used in production. `yarn verify` runs the protocol/API/Worker tests and typechecks both browser and Worker code before the production build.

`yarn verify` also typechecks and bundles the offline companion. The parent repository's separate verification belongs to the retained Quorum messenger and needs its linked sibling repositories and dependencies. Never bypass its bot mint guard.

## Deploy

`yarn build`, then `wrangler deploy`. `wrangler.jsonc` targets the Arca Cloudflare account, the `hypersnap-quorum` Worker, and the `quorum.arca.computer` custom domain. Use your own account/domain when deploying another fork. Authentication is handled by the local Wrangler CLI; credentials never belong in source or browser environment variables.

Copy `.env.example` to your own ignored `.env.local` for local development, or provide `VITE_WALLETCONNECT_PROJECT_ID` in your build environment for wallet app connections. Obtain your own public project ID from the [Reown Dashboard](https://dashboard.reown.com). Allowlist the precise deployed origins in its project configuration. No Dashboard API secret, private wallet key, social login, or hosted account authentication is needed. Vite embeds this public ID into the browser bundle; changes require a rebuild. Missing configuration disables WalletConnect while browser wallet and offline approval remain available.

The Worker serves static assets and adds CSP, no-referrer, no-store HTML, and other browser security headers. API routes use one fixed upstream (`https://haatz.quilibrium.com`), an explicit route/query allowlist, response size/time bounds, and signed binary message submissions limited to 64 KiB. It forwards neither cookies nor authorization headers, follows no redirects, and emits no application request logs. Public images use a dedicated R2 bucket; a SQLite-backed Durable Object enforces upload nonces and daily quotas. Deploy the R2/DO bindings and migration declared in `wrangler.jsonc`; see [MEDIA.md](MEDIA.md) for provisioning, retention, and limits. The upstream node remains a network availability dependency; this version has no failover or independent indexer. Apply appropriate account-level abuse/rate controls before scaling traffic.

## Signing model

The website never accepts a recovery phrase. It generates a random Ed25519 posting key in the browser and asks a compatible wallet app to approve it using `eth_signTypedData_v4`. Desktop extensions and wallet browsers connect through EIP-1193/EIP-6963. The browser-wallet section prioritizes the detected Rainbow extension and connects directly to its provider, including when other extensions are installed; open the site in the browser where Rainbow is installed. Normal Safari/Chrome can also connect a separate wallet app using WalletConnect's encrypted external relay, with a locally generated QR code or explicit mobile wallet links. This optional connection requests typed-data signing only and ends after approval or cancellation; no wallet transaction or Ethereum RPC provider is requested. WalletConnect is an external availability and metadata dependency. No Farcaster-operated login service is involved. The selected wallet must match the public account's custody address. The browser verifies custody signatures before submitting Hypersnap's gasless KEY_ADD.

Default device keys request `[1, 3, 4]`: casts/replies and adding/removing reactions. Following, unfollowing, and editing a profile require a separate, explicit approval for a new key with `[1, 3, 4, 5, 6, 11]`. The dialog displays these added permissions before signing. The current session remains usable until the new key is confirmed; approving the new key does not revoke the old one. Deleting your own casts requires a further explicit key approval for `[1, 2, 3, 4, 5, 6, 11]`, followed by a separate deletion confirmation. All permission sets use a **seven-day sliding inactivity window**, refreshed by protocol activity, rather than a fixed seven-day expiration. The optional offline **Arca Signer v0.2.0** beta supports only the original casts/reactions permissions; use a compatible wallet for the expanded social permissions.

The app exchanges public account data, signatures, and signed protocol messages; custody private keys and recovery phrases remain in the selected wallet or offline companion. WalletConnect adds encrypted transport traffic and temporary pairing material, so its QR code and pairing link must be treated as secrets. The native app denies network requests and has no phrase persistence, telemetry, remote scripts, or updater. Mutable secret buffers are wiped where possible; JavaScript strings and library internals cannot be guaranteed to be zeroed. The browser keeps its posting key in memory unless the user explicitly saves an encrypted IndexedDB vault. On a compatible browser/passkey provider, a passkey’s WebAuthn PRF output derives a local AES-256-GCM encryption key using HKDF-SHA256. Returning users unlock through their passkey provider’s device verification, such as a fingerprint, face scan, or PIN. The PRF output and encryption key never go to our server. Password-encrypted vaults (PBKDF2-SHA256, 600,000 iterations; AES-256-GCM) remain available and older vaults stay compatible. Passkeys unlock an already authorized app key; the first connection, an expired/revoked key, or expanded permissions still require custody-wallet approval. A passkey provider may sync its credential, but this app’s encrypted vault remains in this browser on this exact site. A new browser/device or cleared site storage requires wallet reconnection. PRF support is checked on the actual credential: unavailable support or cancelled setup never silently saves a plaintext key or replaces an existing vault. Locking clears the active key but preserves the encrypted vault. Forgetting removes the vault; revoking removes the current key from Hypersnap, confirms its absence, then erases its saved copy. Revocation can also use an offline custody approval. See [SIGNER.md](SIGNER.md) for the full trust model and release verification.

For a submission timeout, network inclusion is unknown: inspect the profile or signer state before manually retrying. The app never retries writes automatically. Profile fields are separate signed messages: successful fields are retained after a partial save, and uncertain fields remain blocked until their attempted values appear on the public profile. Uncertain follow changes likewise require a status check. Successful submissions are acknowledged by the node, not independently proven finalized.

Image uploads use a constrained, short-lived authorization signed by the existing device key, not another wallet approval. A cast can attach up to two embeds: images and quoted cast references share that limit. Uploaded images are public and persistent, and their original photo metadata, including EXIF, is retained. Removing an image from a draft does not delete its upload; no end-user media deletion flow is included. See [MEDIA.md](MEDIA.md).

## Scope and verification

Implemented:

- Public trending and following home tabs, shareable profile Casts/Replies/Photos/Likes/Recasts tabs, indexed channel discovery/search/detail/feeds and channel posting, bookmarks, dark/light theme, responsive navigation, and session locking.
- Search public casts or people at `/search`; shareable queries and profile tabs survive Back/Forward and direct loads. Cast search is a bounded ranked result set; people search uses the node’s prefix index.
- Recent notifications at `/notifications` for follows, reactions, replies and mentions, with All/Unread/type filters and per-account read state stored on this device. Hypersnap’s bounded activity scan is not a complete historical inbox; the client never calls the node’s placeholder mark-seen POST.
- Protocol quote embeds and confirmed deletion of the connected account’s own casts. Unknown deletion submissions permit read-only reconciliation, with no automatic resubmission.
- Shareable cast links at `/cast/<full-hash>`, public profiles at `/profile/<fid>` or `/profile/<username>`, and the connected account's `/profile` page. Browser Back/Forward and direct page loads restore these views; sharing uses our canonical domain.
- Nested conversation reading with parent links, casts/replies, and like/recast add/remove. Connected-user reaction state uses actual account-scoped protocol receipts after refresh; unknown reaction writes remain blocked in the active session until their intended state is visible. Existing protocol mentions become clickable profile links using validated UTF-8 insertion positions. The composer resolves a username or FID through Hypersnap and inserts an explicitly selected account mention; ordinary unselected `@text` stays literal.
- Public follower/following lists, following/unfollowing after explicit expanded permission approval, and editing display name, bio, or profile image. Banner writes are excluded because Hypersnap requires Pro status and does not reliably hydrate them in its public user response.
- Explicit account/destination-scoped draft Save/Restore/Discard in this browser tab (24-hour TTL), inline mention suggestions with keyboard selection, Ctrl/Command+Enter publishing, pasted-image uploads, an accessible image viewer, copy-cast-text tools, and profile sharing/linked-address details. Drafts contain only text, public mention references and uploaded image URLs; they never contain signing keys or auto-submit.
- Saved channel shortcuts labeled as browser-local, paginated channel participants (accounts that posted), bounded friends-of-friends profile suggestions, and a bounded quote-cast viewer with explicit node-index limits.
- Authenticated public JPEG, PNG, WebP, or GIF uploads up to 5 MiB, with up to two image attachments per cast. The R2/SQLite Durable Object storage and quota boundary is documented in [MEDIA.md](MEDIA.md).

Excluded: creating Farcaster accounts, paid storage/on-chain registration, seed recovery, wallet transfers, DM transport, push notifications, video uploads, end-user media deletion, and mini-app execution. Channel discovery depends on the Hypersnap node’s channel index. Channel parent URLs are protocol identifiers; the client does not contact any external service to resolve them.

See [FEATURE_SUPPORT.md](FEATURE_SUPPORT.md) for the source-backed feature matrix and upstream limitations.

The [MIT-licensed Farcaster client snapshot](https://github.com/farcasterxyz/client) informed familiar sharing, profile, and conversation UX. These features are independently implemented against Hypersnap; no Farcaster-hosted API client, account service, websocket, or source dependency was imported.

Automated checks use synthetic keys, mocked HTTP responses, and an independent Rust protocol golden vector. The project owner reported a successful real Rainbow browser-extension sign-in. Agent-run production checks perform public reads and navigation only; they do not sign real account actions or publish user media. Follow/profile writes and image-backed casts have not been exercised against a real production account by this development session. See [VERIFICATION.md](VERIFICATION.md) for the current checks and limitations. This is a beta, and no independent security audit is claimed.
